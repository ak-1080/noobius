# Work feedback in the world

September 9, 2026. Part of the ongoing Neighborhoods upgrade.

Client jobs, machine loans, fabrication and bonus work now display their current state at the actual worksite. Machine gauges distinguish running work from results awaiting collection. Client indicators open that exact job; service labels preserve ordinary resource-station use. Guided travel also retains the selected job. Directions and indicators do not perform economic actions.

Fabrication stores an optional start time for new batches. Older saved batches retain their finish time and show no invented progress percentage. Completed fabrication stops animating but remains ready until collected. Finite crew loans release their indicator at the recorded deadline. Client and crafting results remain visible until collected. Shared cluster lights distinguish confirmed work from pending machine runs; snapshots expose only an aggregate running count.

Visitors and the public campus receive no private work indicators. Worksite keys are presentation context, never server authority. Effects resolve the physical job target before a claim removes the job. Pausing and reduced-motion preferences stop decorative movement. A keyboard-accessible work list has equivalent entry points and does not leak movement key events into the world.

## Validation

- 192 default tests pass, including five new state/target/privacy/preservation checks. No reward, recipe, contract quote or timer was changed.
- The real local Worker/D1 commissioning test passes with aggregate running-state assertions before and after completion, retries and one reward from competing claims.
- An isolated browser save on port 3003 confirmed running rack → selected job; service label → selected repair; guided arrival → Inspect without completing work; ready fabrication → selected batch without collection; client deadline → payment ready; explicit payment collection → one receipt and a fresh offer. The example intentionally had an overfull bag and correctly retained finished crafting.
- Visual review removed overlapping ordinary and active-work rack labels. The temporary route, seeded browser origin and isolated API database were separate from the existing player's save. Temporary route/configuration were removed before the production build.

This is interaction and correctness evidence, not independent-player acceptance, hosted capacity measurement or proof of long-term enjoyment. Multiplayer still uses HTTP polling. The real holder policy and token payouts remain unconfigured.
