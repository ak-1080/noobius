# October 1 staging admission diagnostic

This staging-only investigation used the existing thirty generated, unfunded QA players across six rooms. It did not create accounts, use a wallet with funds, trade tokens, change signup/admission limits, deploy production, or change the public player cap. Staging room version `af85290b-d55c-4700-9a21-7ef7346d03a9` added fixed-schema timing for admission queue wait, Durable Object storage lookup, game-service ticket consumption, and the whole join. The raw Cloudflare tail remains private under ignored `.wrangler/` because the tail envelope contains client network metadata. The committed facts below contain no identity or network metadata.

The runner requested a six-minute full-speed movement measurement. Thirty players connected. During setup, at about 48.7 seconds after run start, all five sockets in one room closed abnormally (`1006`) within 15 milliseconds. Four recovered in 2.1–2.4 seconds; the fifth recovered in **4,103 ms**, breaching the three-second unexpected-recovery gate. This event was before the measured window, but setup reliability is part of the run, so the overall result is **failed**. The socket close by itself does not prove whether the Durable Object, game service, test host, or network route initiated it. The room tail had `canceled` invocations nearby but no classified application exception or definitive shutdown event.

During the measured window, all thirty players remained connected through thirty planned renewals. The longest planned-renewal recovery was **1,418 ms**, longest sampled peer gap **1,421 ms**, and movement accepted **68,845 / 68,914** requests (99.90%). Movement acknowledgement p95 was **60.4 ms**. All thirty final positions matched their durable saves; cleanup had no errors. These good measurements do not override the setup failure or establish fifty-player safety. This run did not include jobs, trades, mobile browsers, or independent test locations.

The private room tail captured 36 `room-admission-trace` completions. Among those captured, maximum queue wait was **403 ms**, storage lookup **0 ms** at millisecond resolution, game-service ticket consumption **430 ms**, and total join **483 ms**. None captured a multi-second admission. Cloudflare tail output is not a complete per-join ledger: there were more connections than captured traces. The slow setup recovery reached the `ticket` event about 3.8 seconds after disconnect, then opened and joined within roughly 0.3 seconds. The existing timeline did not distinguish delay *before* ticket request from time *inside* that request. The runner now records a redacted `ticket-request` event to separate those on the next replay.

A second thirty-player replay used the new ticket-start timeline with both staging game and room tails running. It requested a 30-second measurement to focus on setup and **passed**: no unexpected interruption, 5,880/5,880 movements accepted, all thirty exact positions saved, and clean cleanup. The authentication path respected a normal minute throttle. This clean short replay did not reproduce the five-socket drop and did not cross the five-minute renewal boundary; it cannot cancel the failed long run.
