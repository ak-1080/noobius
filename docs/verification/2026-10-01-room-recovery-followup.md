# October 1 room recovery follow-up

This work addresses the intermittent multiplayer interruption seen in the September 30 [mixed-capacity qualification](2026-09-30-staging-mixed-capacity.md). It uses only generated QA wallets and staging. Production, the public 50-player cap, owner wallets, real funds and billing were not changed. Private Cloudflare tails remain under ignored `.wrangler/` because they include client network metadata; the linked capacity reports contain bounded counters and event codes, not signing keys.

The browser's unexpected-socket path previously waited for its periodic renewal tick and fetched neighborhood state before obtaining a replacement room ticket. It now starts reconnection immediately using its saved membership; an expired membership still follows the normal rejoin path. This shortens recovery after a transient socket close without pretending the close itself cannot happen.

The room Durable Object also did avoidable work under movement pressure. It sent a separate game-service `authority-refresh` request even when the scheduled movement checkpoint was imminent. With at least six seconds of current authority remaining, it now lets the checkpoint renew authority and persist position together; with less headroom, it retains the early refresh. A retriable checkpoint failure used to close every affected player socket even while the same writer lease still had time. The room now retries the same durable outbox checkpoint after a transient transport/429/5xx failure while that lease has more than 500 ms left. A terminal result or expired lease still closes the socket. The same checkpoint ID is reused, so a response lost after a successful write does not create a second position mutation. Local tests cover this replay and the expiry boundary.

The staging room Worker was deployed for the hosted qualification as version `7b8143fe-0165-41fa-844f-14ecd8e5441c`. A five-player returning-account smoke passed with 958/962 movements accepted, no interruptions and five exact final positions. After the 20-player runs, a fresh ignored staging D1 export was saved at `.wrangler/staging-backups/pre-room-reconnect-2026-10-01.sql`. The guarded devnet-payment staging path verified a zero-obligation payment drain, the private RPC/mint and the hosted login/save/market smoke, then deployed the source with the browser reconnect change on game Worker `99dcd841-3d1e-4f6f-a667-9e7f4bffe42d` and recovery Worker `868ca0c2-5694-44d6-b434-ef4a36e227f6`. The staging marketplace retained its valueless devnet setup. No production Worker was deployed. The first mixed run was started shortly after the room Worker deployment. All twenty clients got code-1006 closes in four room-sized groups about two minutes later. Their reconnections finished within the three-second gate, all four jobs completed, and all twenty positions persisted. Private room logs showed replacement Durable Object constructors with zero attached sockets. That pattern is consistent with runtime restart or rolling deployment, but the initiating cause is **not proven**. The other rooms continued. The subsequent movement-only run had one unexpected drop, recovered within 1.725 seconds, and 19 planned renewals. Both runs used one network location and generated, non-rendering clients; they do not establish browser frame rate, global latency, devnet checkout behavior or 500-player capacity.

The QA harness now obtains each service job's actual materials using ordinary salvage and, where needed, the workbench. It respects the saved account's unlocked zones, node cooldowns and recipes. The immediate repeat above failed because the old harness assumed every part was a salvage node; this is not evidence of a server failure. The corrected mixed repeat completed all four rotated service jobs, all 20 planned room renewals and all 20 exact final saves. It saw no unexpected interruption. This verifies test-account reuse but cannot by itself reproduce or explain the earlier room resets.

The full local rule suite passed 581/581, targeted room/hook tests passed 47/47, TypeScript and the staging build passed, and the isolated release API suite passed. Changed room, event, harness and test files passed `oxlint`; the hook retains six pre-existing React lint findings from outside this edit. `git diff --check` passed.

The current safety decision remains unchanged: keep the public cap at 50 and make no 500-player assurance. Before raising it, repeat sustained mixed room/job/trade/reconnect/save runs after deployments settle, include browser and geographically separate clients, and measure Worker, Durable Object and D1 usage for the exact test interval. The known transient cross-room game-service timeout has not yet been reproduced or explained by these passing runs.
