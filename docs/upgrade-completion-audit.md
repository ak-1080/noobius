## Next implementable work

1. **Visible cooperation while playing — implemented, broader playtest still open.** The compact expandable roster, four presets, scene-bound avatar feedback, request navigation and moderation/lifecycle rules are implemented. See [crew signals](crew-signals.md) for the precise tests and limitations. Real five-person browser/quiet-hour playtests remain required.
2. **Useful operational events — implemented; hosted collection/alerts still open.** Recovery attempts, confirmed/terminal outcomes, expiry, backlog rejection and holder-provider/storage failures use a fixed schema with bounded fields and no authority, wallet, RPC URL or raw error data. Failed batches drain pending siblings before releasing the recovery gate. See [event meanings and validation](operational-events.md). The standalone coordinator is still not deployed.
3. **Read-only recovery verification.** Add an offline auditor for an explicitly supplied backup, opening it read-only. Check schema, malformed saves, negative balances/counts, escrow consistency, contributions/claims and session authority. Distinguish legitimately overdue lazy work from corruption. Exercise a disposable backup/restore fixture and deliberate corruption. This does not replace a hosted recovery drill or invent a complete historical balance ledger.
4. **Independent advanced admission pause — implemented and locally exercised.** New GPU entry and cross-neighborhood travel can pause while free entry, live same-slot recovery, safe return, earned project claims and escrow cancellation remain usable. Dedicated in-place resume prevents a paused takeover from rerunning matchmaking. Real SQLite race cases and an isolated authenticated API scenario cover these rules; hosted operator activation remains unexercised.
5. **Finish world previews and fallback navigation.** Show saved facility development at occupied entrances, provide a real GPU destination preview and make a full/unavailable invitation lead to an explicit alternative-neighborhood choice.
6. **Measure economic sources and sinks by progression.** Existing counters and receipts are not a level-at-event measurement system. Instrument committed outcomes without making telemetry a second economy authority or mistaking player transfers for currency removal.
